# Route Optimizer API

HTTP endpoint used by the React frontend to calculate an optimized route.

## Endpoints

| Environment | URL |
| --- | --- |
| Local | `http://localhost:8080` |
| Production | `https://us-central1-route-optimizer-aebb7.cloudfunctions.net/optimize` |

## Method

`POST`

## Required Headers

| Header | Value |
| --- | --- |
| `Content-Type` | `application/json` |
| `Authorization` | `Bearer <Firebase ID token>` |

The Firebase ID token is generated by Firebase Authentication after the user signs in with Google. Requests without a valid token return `401`.

## Request Body

```json
{
  "destinations": [
    "Antigua Guatemala",
    "Guatemala City",
    "Mixco"
  ],
  "mode": "open"
}
```

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `destinations` | `string[]` | Yes | Between 2 and 15 non-empty destination names or addresses. |
| `mode` | `"open"` or `"closed"` | Yes | Open route does not return to the start; closed route does. |

## Success Response

`200 OK`

```json
{
  "order": [1, 2, 0],
  "total_distance": 42900.0,
  "route_details": [
    "Guatemala City",
    "Mixco",
    "Antigua Guatemala"
  ]
}
```

## Error Responses

| Situation | HTTP Code | Example |
| --- | --- | --- |
| Missing or invalid Firebase token | `401` | `{ "error": "Invalid Firebase token" }` |
| Invalid JSON body | `400` | `{ "error": "Request body must be valid JSON" }` |
| Invalid destination count | `400` | `{ "error": "Destinations must contain between 2 and 15 places" }` |
| Invalid route mode | `400` | `{ "error": "mode must be 'open' or 'closed'" }` |
| Distance exceeds 100 km | `400` | `{ "error": "La distancia entre 'X' y 'Y' (120.5 km) supera el límite de 100 km." }` |
| Unexpected backend error | `500` | `{ "error": "Unexpected error message" }` |

## CORS

The function reads `ALLOWED_ORIGIN` from the environment.

- Local default: `http://localhost:5173`
- Production value: `https://route-optimizer-aebb7.web.app`

Allowed CORS headers are `Content-Type` and `Authorization`.

```bash
cd backend

```

## curl Examples

Get a Firebase ID token from the signed-in frontend session or another Firebase Auth test tool, then pass it as `TOKEN`.

```bash
TOKEN="PASTE_FIREBASE_ID_TOKEN_HERE"

curl -X POST http://localhost:8080 \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"destinations":["Catedral Metropolitana, Guatemala City","Antigua Guatemala"],"mode":"open"}'
```

Missing token test, expected `401`:

```bash
curl -X POST http://localhost:8080 \
  -H "Content-Type: application/json" \
  -d '{"destinations":["Catedral Metropolitana, Guatemala City","Antigua Guatemala"],"mode":"open"}'
```

Invalid payload test, expected `400` when a valid token is supplied:

```bash
curl -X POST http://localhost:8080 \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"destinations":["Solo un destino"],"mode":"open"}'
```

## Deployment Notes

After frontend deployment, redeploy the Cloud Function with:

```bash
gcloud functions deploy optimize \
  --runtime python311 \
  --trigger-http \
  --allow-unauthenticated \
  --region us-central1 \
  --set-env-vars ALLOWED_ORIGIN=https://route-optimizer-aebb7.web.app
```

`GOOGLE_MAPS_API_KEY` must also be configured as an environment variable in GCP. Firebase Admin uses Application Default Credentials in GCP, so the local `service-account.json` file must not be uploaded.
